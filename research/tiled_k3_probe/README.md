# `K > 1` height-strip tiling: implemented and exact

`open_rknpu.tiled_chain.compile_tiled_chain(model, tiles=T, serial=...)` now covers the
whole `chain_n` graph family, so a 3x3 chain can be processed strip by strip. Everything
here is generated by `build_tiled_k3_probe.py` and run by `run_tiled_k3_probe.py` with
`tests/board_bench.c`.

## Layout

A 3x3 strip's output rows `[s*r, (s+1)*r)` need one input row from each neighbour, and
those halo rows belong to the neighbouring strips. The K>1 path therefore switches from
isolated per-strip surfaces to **one shared double-buffered 8x8 native16 surface** per
ping-pong phase: each strip writes only its own rows and reads its window
(`tih = r + 2*h` rows from `top = s*r - h`, `tpt` zero-point rows above the image,
`pl = h`) straight out of that surface. No copy task is needed, and surface bytes are the
same as the isolated layout at 8x8 (two full surfaces either way); the value is a bounded
per-task input fetch, the same reason `native.compile_native_input` height-tiles large
maps. `tiles=1` is the single-strip control.

## Chains

| name | layers | kernels | hidden channels |
| --- | --- | --- | --- |
| `k3` | 16 | all 3x3 | 6 (last 3) |
| `mixed` | 12 | 3x3/1x1 alternating | 4,6,8,10,10,8,6,4,3,3,3,3 |

The untiled serial container is the control and the source of the expected bytes
(`chain_n_reference_layers` over the same quantization chain), so every tiled variant is
checked against the same integer reference on the board, 4 input cases each
(`zeros`, `255`, `128`, random).

## What the board run fixed

1. **Pad value.** Hidden native surfaces store the 128-shifted INT8 value, so the engine's
   input zero point is 0 in that domain: register `0x1184 = 0xff80`, exactly the default
   the untiled chain's native layers use. The first version passed the layer's
   `output_zero_point`, which only changes the padded rows of a 3x3 strip and made every
   tiled case mismatch.
2. **Activation.** The tiled emitter first applied the graph's hidden Relu everywhere;
   the untiled `chain_n` emitter did not (`docs/plans/pipelining-plan.md` S9). The tiled path takes
   each layer's activation from its quantization metadata, so when S9 landed - the
   chain family now applies its hidden Relu - both containers followed without a change
   here, and this suite was re-run (all exact).

Both were isolated by container surgery on the board (patching only those registers) and
are pinned in `tests/test_tiled_chain.py`.
